# Этапы workflow

[English](pipeline.md) · **Русский**

QUICK подходит для локальных изменений. Он использует минимальный план и обычно обходится без субагентов. STANDARD добавляет выборочное исследование и проектирование. FULL подходит для нескольких частей системы и изменений с высоким риском. Независимое ревью определяется политикой и риском.

| Этап | Что фиксируется |
|---|---|
| CLASSIFICATION | Масштаб, компоненты, исследование, дизайн, параллельность, риск и потребность в аудите |
| RESEARCH | Релевантные файлы, зависимости, ограничения и проверки |
| DESIGN | Интерфейсы, потоки данных и компромиссы |
| PLANNING | Порядок действий, зависимости и критерии готовности |
| IMPLEMENTATION | Фактические правки, отличия от плана |
| TESTING | Реальные команды, результаты и ограничения проверок |
| REVIEW | Подтверждённые замечания, отсутствие замечаний или причина пропуска |
| FINAL_REPORT | Итог, проверки, риски, модели и ID запуска |

CLASSIFICATION, IMPLEMENTATION, TESTING и FINAL_REPORT обязательны. У пропуска есть причина в состоянии или артефакте. При пакетной записи все записи проверяются до сохранения, затем состояние обновляется одной ревизией. При прерывании состояние — источник истины.

Если проверка блокирует запуск, применяется не более одного автоматического цикла исправлений. Предыдущие отчёты архивируются. Проверьте фактические файлы перед продолжением и завершайте уже начатую попытку исправления, если она была прервана. Ручные правки и состояние исходников не откатываются.
