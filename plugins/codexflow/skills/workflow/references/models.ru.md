# Политика моделей

[English](models.md) · **Русский**

`allowed_models` присваивает точным ID категории `economy`, `standard` или `premium`. Для премиальных моделей требуется `allow_premium: true`: его включает профиль performance или явный параметр. Astra допустима только как premium. Известная модель вне политики отклоняется. При скрытой модели текущая сессия отмечается как неподтверждённая.

Роль задаёт `model` (точный ID или null), `reasoning_effort` (null для наследования) и `fallback` (`stop`, `parent` или разрешённый ID). При `model: null` применяется fallback. Наследование разрешает использовать модель родителя с её категорией стоимости.

В режиме auto скрипт читает видимые ID Sol/Luna/Astra и поддерживаемый reasoning из нативного каталога. Подбирается самая свежая числовая версия внутри допустимого семейства и не ниже настройки роли. Если клиент сообщает доступные ID, этот список сужает выбор. Если каталог недоступен, действует настроенная база. Режим pinned сохраняет точные ID.

Клиент управляет моделью и reasoning главной сессии. Допустимая текущая модель сохраняется. Если ID скрыт, разрешённый запрос можно выполнить с пометкой `actual=unconfirmed`. Для дочерней роли `resolve` возвращает запрошенную модель, подтверждение приходит из нативного запуска, когда клиент его предоставляет. Каталог сам по себе не подтверждает доступ аккаунта.

При сбое выбора передайте `--failed ID`, сообщите причину и попробуйте только разрешённый fallback. Встроенное значение `stop` прекращает выбор. Для `parent` нужен известный разрешённый родительский ID. Используйте реальные параметры нативного инструмента, а при отсутствии выбора модели или reasoning сообщайте это ограничение.
