# Журнал и восстановление запуска

[English](journal.md) · **Русский**

Для вызова скрипта используйте `python3 /.../scripts/journal.py --root PROJECT`. Команда `doctor` показывает источник профиля, запрошенную и подтверждённую модели, правила делегирования и регистрацию хуков. Доступность модели и инструментов подтверждается по данным текущего клиента.

## Проверки, статус и продолжение

`check RUN --phase targeted --watch src/parser.py --watch tests/test_parser.py -- python3 -m unittest tests.test_parser` выполняет реальную команду. Сначала проверяйте затронутую часть, затем запускайте `--phase full`, если этого требуют правила проекта или риск для других частей. Не передавайте секреты в аргументах. Журнал хранит код выхода, длительность, путь к логу и SHA-256 отслеживаемых файлов. Полный вывод остаётся в папке запуска.

`--reuse` подходит для воспроизводимых проверок с полным списком исходников, тестов, конфигурации и lock-файлов при неизменном окружении. Внешние и неотслеживаемые данные вне этой гарантии. Если файлы изменились во время проверки, её результат нельзя переиспользовать. Упавшая проверка сохраняется со своим кодом выхода.

`status RUN` показывает этапы, выполненные команды, события нативных агентов, изменения файлов, серию задач и покрытие статистики. Записывайте события агента командой `agent RUN THREAD ROLE started|completed|failed|cancelled [--model ID]` с реально полученным ID.

При продолжении сначала проверьте `status`. Если после реализации изменились отслеживаемые файлы, `recheck RUN` архивирует старые результаты тестов, ревью и отчёт и открывает эти этапы заново. Исходники и счётчик исправлений сохраняются. Повторите затронутые проверки. У старых запусков отпечатков нет, пока для них не записаны проверки.

## Серия задач

Флаг `--series` в запросе к Skill включает общий план и отдельные статусы для нескольких результатов. Передайте `series init RUN --file PATH` список JSON с полями `id`, `title` и необязательным `depends_on`. Зависимости должны идти раньше в списке.

Для каждого элемента запустите `check RUN --phase targeted --item ID --watch FILE -- COMMAND ...`. Успешную актуальную проверку привяжите через `series set RUN ID complete --check-id CHECK --summary "Результат проверен"`. Блокер запишите через `series set RUN ID blocked --summary "Причина"`. Изменение элемента или новая проверка зависимости делают прежнее подтверждение зависимых элементов устаревшим. Независимые готовые элементы сохраняют статус, если их файлы не изменились. Перед итогом все элементы должны быть готовы.

## Опциональный сбор токенов

`usage enable` добавляет в проектный `.codex/hooks.json` обработчики CodeFlow. Сбор по умолчанию выключен. В Codex нужно просмотреть и подтвердить хуки, а клиент должен поддерживать PostToolUse и PostModelRequest. В файле хуков локальные пути. Храните его вне истории Git.

`usage bind RUN` связывает запуск с точной парой сессии и запроса через PostToolUse. Запускайте команду отдельно. Когда клиент отдаёт оба ID, их можно передать через `--session-id` и `--turn-id`. Хук хранит только числовые счётчики, ID модели, запроса и субагента при наличии. Промпты, содержимое чатов и аргументы команд этот хук не сохраняет. Покрытие частичное. Начальный запрос, события после завершения, неподдерживаемые события и отдельно запущенные субагенты могут отсутствовать. Входные, выходные, кэшированные и reasoning-токены показываются отдельными полями. Это не остаток лимита подписки.

`usage status` показывает регистрацию, `usage show RUN` — собранные цифры, `usage disable` удаляет только регистрации CodeFlow. Старые записи остаются.
