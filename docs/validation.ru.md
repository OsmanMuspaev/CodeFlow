## Версия 1.3.0

Прошли 37 тестов и оба валидатора. Проверены отказ до создания запуска при запрещённой модели, пакетная валидация до записи, восстановление после упавших тестов, stale revision и прежние поэтапные команды.

Для типичной небольшой правки прежняя схема предусматривала 13 вызовов helper. Новый путь использует три вызова: подготовка запуска, запись классификации и пропусков, запись реализации, тестов и отчёта. Для долгих проверок можно отдельно сохранить реализацию перед тестами.

На двух изолированных задачах сравнили обычный Codex и QUICK с одинаково запрошенными GPT-6.2 Sol и medium. В обеих ветках каждой задачи прошли все четыре исходных теста. QUICK завершил оба запуска и сохранил отчёты. В одном запуске было три успешных вызова helper и одна повторная попытка из-за формата результата; после проверки инструкция уточнена. Во втором запуске хватило трёх вызовов helper. Точный расход токенов недоступен, скорость и расход статистически не сравнивались.

## Отсутствующая runtime identity (1.0.2)

В 1.0.1 отсутствие exact model ID у клиента останавливало workflow. Это делало запуск невозможным даже с корректной конфигурацией Sol/Luna. В 1.0.2 `resolve` принимает отсутствие `--parent` и `--available` как отсутствие метаданных. При явном разрешённом target работа продолжается; `requested_model` сохраняется отдельно от `actual_model: null`, `runtime_verification: unconfirmed`. Неизвестная availability не превращается в подтверждённую доступность.

Добавлены регрессионные проверки всех ролей без метаданных, реального CLI-запуска resolve, известных запрещённых/несовместимых родителей, отсутствующей Luna, ошибки выбора без fallback, неизвестного parent fallback, пустого allowlist и несовместимых targets двух main-ролей. Эти проверки не удостоверяют скрытую модель хоста; это явное ограничение Skill. При отсутствии runtime metadata нельзя гарантировать стоимость или независимо подтвердить модель главного агента.

## Настоящая установка plugin

Создан отдельный marketplace и временный `CODEX_HOME`.

```text
codex plugin marketplace add <temporary-marketplace> --json → exit 0
codex plugin add codexflow@codexflow-local --json → exit 0
```

Codex принял manifest, зарегистрировал marketplace и установил `codexflow@codexflow-local`, версия `1.0.0`, во временный plugin cache. Это операции управления plugin, не вложенный агентный CLI-запуск. Глобальная конфигурация пользователя не менялась.

Для версии `1.0.1` дополнительно проверено обновление с `1.0.0` в отдельном временном `CODEX_HOME`: повторный `codex plugin add codexflow@codexflow-local --json` завершился с exit 0 и установил `1.0.1`. В cache проверены Sol/Luna defaults. В версии `1.0.2` отдельно проверено штатное обновление с `1.0.1` в изолированном `CODEX_HOME`: повторный `plugin add` установил `1.0.2`; запуск установленного `resolve orchestrator_model` без `--parent` и `--available` завершился с exit 0, requested Sol, actual null и обеими проверками unconfirmed. `plugin marketplace upgrade` для локального marketplace не подходит: CLI допускает эту операцию только для Git-источника; для этого пакета используется повторный `plugin add`.

## Поведенческий QUICK smoke test

Независимый нативный агент с новым контекстом, явно выбранный host tool с `model=gpt-6-luna`, `reasoning_effort=medium`, прочитал Skill и выполнил задачу в отдельном тестовом проекте.

Задача: исправить `add(a, b)`, возвращавшую `a - b`. Два unittest сначала падали, после исправления на `a + b` прошли. Команда из корня fixture:

```text
python3 -m unittest discover -s tests -v → exit 0; 2 tests passed
```

Главный агент независимо повторил команду в fixture: **2 tests passed**. Попытка запустить те же тесты из корня исходников через абсолютный `-s` сначала дала ImportError для `src`; повтор из правильного working directory прошёл. Ошибка invocation не потребовала изменения кода.

Run ID: `20261117T093603Z-a7568854`, state `complete`, revision 8. Сохранены task.md и все восемь результатов этапов; исследование/дизайн/план/review пропущены с причинами. Внутри QUICK не создавались subagents; внешний агент использовался только для независимого тестирования самого Skill.

Выбранная модель известна по параметру нативного spawn. Отдельного runtime-подтверждения модельного ID инструмент не предоставил; это явно отмечено в итоговом отчёте fixture. Расход токенов неизвестен. Первый проверяющий агент без такого выбора не смог установить actual ID и остановился по тогдашней политике fail-closed. В 1.0.2 именно эта избыточная блокировка устранена; неизвестная модель больше не считается доказанно запрещённой.

## Поведенческие STANDARD и FULL smoke tests

Тот же независимый economy-агент выполнил два дополнительных forced-mode запуска в отдельных проектах. Реальный scope честно классифицирован как небольшой; FULL не использовался как повод создавать ненужных агентов.

| Режим | ID запуска | Реализация | Проверка |
|---|---|---|---|
| STANDARD | `20261117T093935Z-0c9392e9` | Inclusive фильтрация чисел и валидация границ | 3 unittest, exit 0 |
| FULL | `20261117T093935Z-9cc3b496` | FIFO очередь, порядок и исключение при пустом состоянии | 2 unittest, exit 0 |

В обоих запусках созданы research/design/plan и прочие артефакты; state `complete`, revision 8. `status` прочитал сохранённые запуски. Главный агент отдельно повторил тесты из корней обоих fixture: все прошли. Независимый review пропущен с конкретным обоснованием малого риска; интеграционный аудит большого FULL-проекта этим не подтверждается. Вызовы дочерних агентов внутри этих workflow не выполнялись.

## Независимая проверка реализации

Read-only проверяющий агент подтвердил ошибки interrupted repair и использования непроверенного artifact path из сохранённого JSON. Обе исправлены и покрыты регрессионными тестами. Исправление interrupted repair дополнительно перепроверено агентом. Проверка source не доказывает, что модель всегда будет следовать всем инструкциям Skill.

## Ограничения доказательств

Вызовы реальных платных/недоступных моделей не выполнялись ради проверки ошибок; соответствующая политика проверена unit tests. Цены, квоты и непрозрачные алиасы модельных ID не проверяются автоматически. Не проверялись hosted-клиенты без локального Python, публичная публикация в Plugins Directory, большие репозитории и долговременная статистика экономии токенов.
